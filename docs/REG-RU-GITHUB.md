# Как подключить домен REG.RU к сайту «Глубже»

Для Виктории Носковой, преподавателя йоги. Обновлено 27 ноября 2026 года.

**Сайт:** https://tonykurman.github.io/tishe-yoga/  
**Исходники:** https://github.com/TonyKurman/tishe-yoga

Сайт уже можно показывать ученикам по ссылке выше. В адресе сохранилось техническое имя проекта `tishe-yoga`. После подключения своего домена вы сможете делиться новым адресом.

Домен — ваш адрес, например `ваше-имя.ru`. Сейчас сайт размещён на GitHub Pages. Для подключения этого макета отдельный хостинг на REG.RU покупать не требуется. Это инструкция по подключению адреса; перенос сайта на оплаченный хостинг REG.RU — другой сценарий.

## 1. Что подготовить клиенту

Если вы пока только создали аккаунт REG.RU, сначала зарегистрируйте выбранное доменное имя на себя. Если домен уже есть, повторно покупать его не нужно. Сообщите разработчику **только название домена**. Для настройки не нужно пересылать пароли от REG.RU или GitHub.

Клиент управляет доменом на REG.RU. Настройки GitHub в текущем проекте выполняет владелец аккаунта **TonyKurman**: у нового клиента автоматически нет доступа к разделу Settings этого репозитория.

## 2. Сначала подготовить GitHub — делает владелец репозитория

Рекомендуемый первый шаг: в личных настройках GitHub откройте **Settings → Pages → Add a domain**. Добавьте домен. GitHub покажет TXT-запись: передайте клиенту её имя и значение, клиент добавит их в REG.RU, после чего нажмите **Verify**. TXT-запись сохраните. Это подтверждает владение доменом. [Инструкция GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages).

Затем откройте [Settings → Pages проекта](https://github.com/TonyKurman/tishe-yoga/settings/pages). В **Custom domain** укажите свой настоящий домен без `https://` и без `/tishe-yoga/`, нажмите **Save**. Источник публикации оставьте **GitHub Actions**. Только после этого меняйте A/CNAME-записи. [Порядок подключения GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## 3. Настроить DNS на REG.RU — делает клиент

Войдите в личный кабинет, выберите свой домен и проверьте, какие DNS-серверы у него указаны:

- `ns1.reg.ru` и `ns2.reg.ru` — записи редактируются в личном кабинете REG.RU.
- `ns1.hosting.reg.ru` и `ns2.hosting.reg.ru` — в панели хостинга.
- Другие серверы — в панели соответствующего DNS-провайдера.

Откройте управление DNS-записями выбранного домена. Названия разделов могут отличаться. **Не меняйте DNS-серверы наугад**: если уже работает почта, нужно сохранить её записи. [Как найти нужную панель REG.RU](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-dns-dlya-domena).

Добавьте четыре A-записи для основного адреса и CNAME для `www`:

| Тип | Имя / поддомен | Значение |
| --- | --- | --- |
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `tonykurman.github.io` |

TTL оставьте по умолчанию. Если панель требует точку в конце CNAME, используйте `tonykurman.github.io.`. Значение `www` содержит только имя хоста: без `https://`, без имени репозитория и без `/tishe-yoga/`.

Старые конфликтующие A/AAAA/CNAME для `@` и `www` замените после проверки их назначения. MX/TXT почты сохраните. Не создавайте запись `*`. [Значения DNS из справки GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## 4. Дождаться проверки и включить HTTPS

Владелец GitHub возвращается в **Settings → Pages**. После успешной DNS-проверки и выпуска сертификата включает **Enforce HTTPS**. Обновление DNS и доступность этой настройки могут потребовать до 24 часов. [HTTPS в GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https).

Проверьте основной домен и адрес с `www` на компьютере и телефоне. Должны открываться фотографии, меню, статьи и галерея, а браузер — показывать защищённое соединение. После подключения разработчик обновит абсолютный адрес изображения для предпросмотра ссылки.

2. В разделе «Мои практики» перейдите к расписанию. Пока опубликована примерная неделя, цены и формы записи демонстрационные.

## Как передать следующие изменения

Для обновления расписания пришлите разработчику название занятия, день, время, часовой пояс, длительность, уровень и место или онлайн-формат. Для публикации цен укажите стоимость разового занятия, условия и срок действия абонемента.

Если вы сами редактируете сайт и владелец предоставил доступ к репозиторию, откройте [тексты и контакты](../dist/index.html) или [расписание](../dist/content.js), нажмите карандаш и сохраните изменения в `main` через **Commit changes**. Статус публикации появится в [Actions](https://github.com/TonyKurman/tishe-yoga/actions). Когда публикация завершится, откройте страницу и проверьте изменённый раздел.

Если сайт позже переезжает в собственный GitHub клиента, потребуется отдельно перенести репозиторий/настроить Pages и заменить `tonykurman.github.io` на адрес нового владельца. Эта инструкция рассчитана на **текущий** репозиторий.
